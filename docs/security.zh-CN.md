# 安全说明

[English](security.en.md)

## 工作方式

程序在一个特权容器中运行。它提供网页，经 `/proc/1/root` 读取主机，并把每次确认的更新作为主机上的临时 `systemd` 单元启动。该单元以 `task run` 模式运行同一个程序，需要构建时再启动一次性构建容器。驱动是一个 `systemd-sysext` 镜像，即 TrueNAS 合并进 `/usr` 的打包驱动。程序替换正式路径（`/usr/share/truenas/sysext-extensions/nvidia.raw`）上的镜像文件，卸载并重新合并一次，再核对已加载的驱动版本。任务完成以任务状态文件为准，不以 systemd 状态为准。运行镜像基于空镜像（`scratch`），没有 shell 和构建工具，所以应用的命令行按钮没有可启动的东西。

## 安全模型

- 特权容器与 `pid: host` 允许进入主机命名空间、修改驱动文件及卸载和加载内核模块。程序、镜像和数据目录的访问权限应视为主机管理员权限。
- 服务默认在容器内的 `0.0.0.0:8199` 提供明文 HTTP。默认 bridge 映射 `8199:8199` 会将端口发布到主机的所有接口；也支持 macvlan 与 ipvlan。请限制为可信管理局域网访问，不要暴露到公网。
- 只有一个管理员账号。还没有账号时，应用会把一次性设置码写进自己的日志。打开程序页面并输入设置码的人，设定管理员密码并直接登录；用户名默认为 `admin`。YAML 里没有密码。持有设置码的人能创建首个账号，请尽快完成设置并保护应用日志。设置码只出现在应用日志中，单次有效，24 小时后失效；重启会生成新码。输错不会替换仍有效的设置码。设置码错误、密码登录失败与 SSH 密钥登录失败共用同一个限流。未配置 TLS 前端时，设置码与密码通过明文 HTTP 传输。忘记密码时，删除凭证文件后重新设置，见[运维说明](operations.zh-CN.md)。
- 已认证 API 请求必须同时携带签名会话 cookie 和该会话的 `X-NVM-Token`。只有非 `GET`/`HEAD` 请求接受 Origin 检查。会话有效期为 12 小时，cookie 带 `HttpOnly` 与 `SameSite=Strict`。两者都应保密。程序不会给 cookie 添加 `Secure`，部署条件见下文。
- 智能体可以用管理员登记的专用 SSH 密钥签署一次性挑战登录，程序只接收公钥与签名。这会取得同样的管理员会话，不会开启 SSH 服务，也没有权限更低的智能体角色。删除公钥会作废已有会话。每次替换、重试和换回原版前，智能体必须展示准确计划并取得人的确认；API 无法证明确认来自人。详见[智能体说明](agent.zh-CN.md)。

## 已知限制

- 替换驱动可能中断显卡工作负载。程序会报告使用者并拒绝不安全的计划，但不会代停应用。自动恢复需要已保存的原版驱动，恢复本身也可能失败。请备份数据目录，并准备主机控制台访问方式。
- 构建使用一次性容器，禁用网络、移除全部 capability，并设置 `no-new-privileges`，但未设置 CPU、内存或进程数上限，可能与主机服务争用资源。下载与构建默认合计共用 30 分钟时限。
- 程序不内置 TLS。HTTPS 反向代理须保留请求的 host/origin，并保护后端连接。程序不会根据转发头给 cookie 添加 `Secure`；浏览器收到的 cookie 是否带该属性，取决于部署侧是否重写。仅终止 TLS 不会添加该属性。
- 上传的安装包会在构建中执行，并生成要加载到主机内核的代码。只上传可信文件，并与可信来源核对 SHA-256。校验值只能标识字节，不能证明来源。
- 联网构建依赖 NVIDIA 下载、Docker Hub 和 Debian 快照软件包。在 `6.12` 或 `6.18` 内核上使用官方 `470.256.02` 驱动时，主机还会从 snapshot.debian.org 下载社区补丁归档，与构建软件包使用同一来源。下载或校验失败会停止准备；查看任务日志，解决原因后重试。离线构建必须提前准备固定的构建镜像与软件包。
- 社区补丁驱动不支持用户 I/O 内存映射，启用 IBT 时无法加载，显示热插拔行为可能不同；Kepler 的加载、显示与 CUDA 工作负载尚未验证。请遵守所选来源的警告。
